# Database design

## Conventions

- Primary keys are UUIDs generated by Prisma. Join tables use composite primary keys.
- Timestamps use PostgreSQL `TIMESTAMPTZ(3)` and are written in UTC. Due dates use `DATE` because they are calendar dates.
- `createdAt` is immutable. Prisma maintains `updatedAt`. Lifecycle timestamps such as `deletedAt`, `revokedAt`, `endedAt`, and `validUntil` describe state without erasing history.
- Realtime avatar transforms and heartbeat samples are deliberately absent. PostgreSQL stores presence transitions, not render-frame state.

## Identity and authorization

`UserRole` gives users one or more roles. The migration seeds `ADMIN`, `SUPERVISOR`, and `MEMBER`. `RolePermission` supports later permission grants without changing the user schema. API and socket authorization must check both an active role assignment and the resource scope.

`ReportsTo` is the organization structure. A member can have multiple active supervisors. Closing a relationship sets `validUntil`; a partial unique index prevents duplicate active member/supervisor pairs. Application transactions must verify that the target supervisor has an active `SUPERVISOR` role. Administrators bypass reporting scope only through explicit authorization rules.

`AllowedEmailDomain` is backend-owned configuration. The migration seeds `mail.kmutt.ac.th`, `kmutt.ac.th`, and `ad.sit.kmutt.ac.th`. Authentication must normalize the verified email and query an active exact domain match.

`AuthIdentity` maps an opaque identity-provider subject to a user. `AuthSession` stores a hash of the session token, never the bearer token itself.

## Enum values

- Roles: `ADMIN`, `SUPERVISOR`, `MEMBER`.
- Work status: `AVAILABLE`, `WORKING`, `IN_MEETING`, `FOCUS`, `BREAK`, `AWAY`, `INACTIVE`, `OFFLINE`.
- Task status: `BACKLOG`, `TODO`, `IN_PROGRESS`, `REVIEW`, `DONE`.
- Task priority: `LOW`, `MEDIUM`, `HIGH`, `URGENT`.
- Meeting state: `SCHEDULED`, `ACTIVE`, `ENDED`, `CANCELLED`.
- File scan state: `PENDING`, `CLEAN`, `REJECTED`, `ERROR`.

The complete enum definitions are in `schema.prisma`; application protocols should reuse generated Prisma enum types rather than duplicate string lists.

## Deletion and retention

Users, rooms, tasks, comments, submissions, and meetings are soft-deleted or archived first. Required audit relationships use `RESTRICT`; dependent join rows and child records use `CASCADE` only during an approved final purge. Files must be deleted from object storage before their metadata rows are hard-deleted.

`ActivityEvent` and closed `Presence` rows expire after 90 days. Both carry model the minimum transition needed for availability and escalation; neither stores key contents, pointer paths, screenshots, camera data, or avatar positions. `retention.sql` is the worker-safe purge statement. Run it at least daily. It intentionally excludes active presence rows.

Work-session retention defaults to 365 days after check-out and is set through `retentionExpiresAt` when the session closes. Legal holds and approved retention exceptions belong to a later compliance workflow and must suspend purge explicitly rather than silently changing the organization-wide default.
